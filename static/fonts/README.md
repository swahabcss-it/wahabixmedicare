# Enabling Urdu in Downloadable PDFs

## Where Urdu already works (no action needed)
The **"🖨️ Print (Letterhead)"** button on prescriptions renders an HTML
page that your browser prints — browsers render Urdu/Nastaliq correctly
on their own using whatever Urdu font is installed on your Windows PC.
This already works today.

## Where Urdu needs one extra step
The **downloadable PDF** versions (View PDF / Download PDF buttons, and
anything a patient downloads from the Patient Portal) are generated by
Python's ReportLab library, which does **not** know how to draw Urdu
script out of the box — it needs an actual Urdu font file to be told
about. That font file wasn't available to include automatically (no
internet access in the environment this was built in).

## How to enable it (2 minutes, one time)

1. Download a free Urdu font — recommended: **Noto Nastaliq Urdu**
   https://fonts.google.com/noto/specimen/Noto+Nastaliq+Urdu
   (click "Download family", unzip it)

2. Find the file named `NotoNastaliqUrdu-Regular.ttf` inside the
   downloaded folder.

3. Copy it into this exact location in your project:
   ```
   wms/static/fonts/NotoNastaliqUrdu-Regular.ttf
   ```

4. Restart the server (`python manage.py runserver`).

That's it — no code changes needed. `apps/core/services/pdf_service.py`
automatically detects the file at startup and registers it. If the file
is missing, Urdu text is safely replaced with a placeholder in the PDF
(pointing to the Letterhead print or Patient Portal instead) rather than
crashing PDF generation or showing blank boxes.

## Verifying it worked
Write a prescription with Urdu instructions, then click "Download PDF"
(not "Print Letterhead" — that one already worked). If the Urdu text now
appears instead of the placeholder message, it's working.
